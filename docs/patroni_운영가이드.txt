============================================================
  Patroni 환경 운영 정리
============================================================

[ 서비스 기동 / 종료 / 상태 ]

  sudo systemctl start patroni
  sudo systemctl stop patroni
  sudo systemctl status patroni


[ 클러스터 상태 확인 ]

  patronictl -c /postgres/app/etc/patroni/patroni.yml list


[ PostgreSQL만 재시작 (Patroni 유지하면서) ]

  patronictl -c /postgres/app/etc/patroni/patroni.yml restart pg-cluster


[ reload (postgresql.conf 변경 반영) ]

  patronictl -c /postgres/app/etc/patroni/patroni.yml reload pg-cluster


[ Switchover (계획된 역할 전환) ]

  patronictl -c /postgres/app/etc/patroni/patroni.yml switchover pg-cluster


------------------------------------------------------------
  노드별 Patroni 정지 시 동작
------------------------------------------------------------

  ▶ Primary Patroni 정지 시
    - PostgreSQL도 같이 내려감
    - Standby가 etcd에서 Leader 없음 감지 (TTL 30초 대기)
    - Standby가 자동으로 Leader 승격 (자동 failover)
    - Primary 재기동 시 자동으로 Standby로 복귀

  ▶ Standby Patroni 정지 시
    - 복제만 끊김, Primary는 계속 운영
    - 재기동 시 자동으로 다시 붙음 (서비스 영향 없음)

  ※ 주의: pg_ctl로 직접 PostgreSQL을 내리면
           Patroni가 즉시 재기동시키거나 충돌이 생길 수 있음
           HA 환경에서는 반드시 Patroni를 통해 제어할 것


------------------------------------------------------------
  sudo 권한 관련
------------------------------------------------------------

  systemctl start/stop  → sudo 필요
  patronictl            → sudo 불필요 (postgres 유저로 직접 실행 가능)

  현재 설정 (보안취약점 가능성 있음):
    postgres ALL=(ALL) NOPASSWD: ALL

  권장 설정 (최소 권한):
    postgres ALL=(ALL) NOPASSWD: /usr/bin/systemctl start patroni
    postgres ALL=(ALL) NOPASSWD: /usr/bin/systemctl stop patroni
    postgres ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart patroni
    postgres ALL=(ALL) NOPASSWD: /usr/bin/systemctl status patroni

  → 최소 권한으로 줄이면 보안취약점 지적 없이 start/stop 계속 사용 가능
  → /etc/sudoers.d/postgres 파일을 위 내용으로 교체
